Supplementing queries with functions
Queries, like the one we created in the last exercise, often start off as basic data retrieval
from our source tables. In this exercise, we will expand on this query and, using different
functions, gain more insight our query results.

1. Open your query "Insurance Claim Analysis" from the previous exercise.
If you can't find this, open the query "ex_ch3_5_supplementing_queries_with_functions" from 
the Queries section.

2. Assuming these are each customer's first claims, we want to ensure timely and sufficient support.
    Using the date_diff function, update the existing query to include the following new fields:
        "CustomerMonths", as the number of months between the POLICY_EFF_DT and REPORT_DT fields.
        "PaymentDays", as the number of days between the REPORT_DT and TXN_DATE_TIME fields.

3. These metrics help identify customer groups with varying churn risk, which is the 
likelihood that a customer will stop doing business with the company. Newer customers 
with longer payment delays may be more likely to churn, and vice versa.

Update the query to include a new field, called "ChurnRisk", which uses the 
CustomerMonths and PaymentDays as evaluation criteria.

SELECT 
    CUSTOMER_ID,
    PREMIUM_AMOUNT,
    CLAIM_AMOUNT,
    POLICY_EFF_DT,
    REPORT_DT,
    TXN_DATE_TIME,
    INSURANCE_TYPE,
    HOUSE_TYPE,
    INCIDENT_STATE,
    INCIDENT_SEVERITY,
    date_diff(MONTH, POLICY_EFF_DT,REPORT_DT) AS `CustomerMonths`,
    date_diff(DAY, report_dt, TXN_DATE_TIME) AS `PaymentDays`,
    CASE 
        WHEN CustomerMonths <= 12 AND PaymentDays > 30 THEN 'High'
        WHEN CustomerMonths > 12 AND PaymentDays <= 30 THEN 'Low'
    ELSE 'Medium' END AS `ChurnRisk`
FROM insurance
WHERE INCIDENT_SEVERITY != 'Minor Loss'

4. Which of the following statements best summarizes the purpose of the functions we used in this query?
R:We calculated specific KPIs on customer response time using date_diff, and we used the CASE statement to compare specific criteria and put customers into different "buckets" based on risk.

Filters and parameters
Filters
Creates a sub-selection of the resulting rows based on the specified value or criteria
Functions the same as a WHERE clause in a SQL query
  Text-based, numerical, date ranges, dropdowns

Parameters
Arbitrary text values that can be injected into a SQL query
Often can be used as a filter
Also able to inject other text values
  Dynamically add fields to query
  Change the behavior of a function

Using parameters in queries
Filters are a great way to add in a sub-selection capability to our dashboards, 
but can be somewhat limited depending on what we are trying to accomplish.
In this exercise, we will explore a basic example of how to use a parameter in our dashboard 
to better provide interactivity to our end users

1. 
Navigate to the Dashboards section and open your "Agent Analysis Dashboard" you created in the previous exercise.
Reset all of the filters previously applied to the dashboard.

2.
Open the Data tab of the dashboard and go into your Insurance Agent query.
Add a WHERE clause to the bottom of your query. This WHERE clause should use the LIKE operator to compare the AGENT_NAME field against a string.
Add a parameter and call it "agentName". To update the name of your parameter, change the text after the : in your query after you insert the parameter.
Put this parameter in between two % symbols using the concat() function so we have wildcard operators in our search.
Here is an example of what this function would look like: concat('%', :parameter, '%')
Press Run to run your query.

SELECT I.*,
    E.AGENT_NAME
FROM INSURANCE I 
LEFT JOIN employee E 
ON E.AGENT_ID = I.AGENT_ID
WHERE E.AGENT_NAME LIKE concat('%', :agentName, '%');

3.
Navigate to a page tab on your dashboard and add a new filter widget to the canvas.
Put the agentName parameter in this filter.

4.For all agents with "Steve" in their name, which `INSURANCE_TYPE` has the highest claim amount?
R: Property
Correct! You correctly inserted a parameter into your query, allowing for more sophisticated filtering logic to your overall dashboard.
